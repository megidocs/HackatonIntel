‫כל הרכיבים פועלים ונבדקו. שיבוץ, מודל השפה והסוכן רצים במחשב ההדגמה. ה-AI מציע, והמוקדן מאשר.‬

הארכיטקטורה כפי שהיא בקוד היום. במרכז שרת FastAPI בפייתון, שרץ בשני מקומות: באופן מקומי במחשב ההדגמה, ובאופן ציבורי בשירות Render החינמי, בתוך קונטיינר Docker ובכתובת HTTPS. השרת מחזיק את שעון הסימולציה, מחשב מסלולים ב-A* על גרף הרחובות של מנהטן, מתזמן את הגל הירוק ומתריע לאזרחים בדרך. מימין הלקוחות, וכולם רואים את אותו מצב סימולציה: הסימולטור בדפדפן, ואפליקציית Android שנבנתה ב-Flutter, בתפקיד נהג ההצלה ובתפקיד האזרח. הטלפונים מקבלים עדכוני WebSocket כל 200 מילישניות. באבן הדרך החמישית נוספו שיבוץ והרשאות: מסד PostgreSQL ב-Supabase עם שש טבלאות ואבטחה ברמת השורה, כניסה דרך Supabase Auth שמנפיק אסימון JWT, ותפקיד לכל משתמש: מוקדן, נהג הצלה או אזרח. טרנזקציה מונעת שיבוץ של אותו רכב לשני אירועים, ו-Redis במחשב ההדגמה מחזיק את המיקום האחרון ומונע שידור חוזר. השיבוץ המאומת פועל כרגע במחשב ההדגמה בלבד. בשרת הציבורי הוא כבוי, ושינוי התרחיש שם מוגן בקוד מציג. באבני הדרך 6 ו-8 נוספו מודל השפה Qwen3 ועוזר המוקדן. המודל רץ במחשב ההדגמה עצמו, דרך llama.cpp, ולכן אין תשלום לכל קריאה ואין שליחה של דיווחים לשירות חיצוני. הוא מנסח טיוטת אירוע מדיווח חופשי, והסוכן משתמש בכלים של המערכת, כמו מנוע הניתוב ולוח השיבוץ, כדי להציע שיבוץ שהמוקדן מאשר. גם הם פועלים כרגע במחשב ההדגמה בלבד. משמאל, GitHub Actions בודק כל שינוי לפני ש-Render מפרסם אותו. עיקרון הבטיחות: ה-AI רק מציע, ופקודות לרמזורים ושיוך רכבים עוברים בקוד דטרמיניסטי.
