# פרופיל הבוגר ומחוון המגמה · ClearPath AI

[מחוון השיפוט של ההאקתון](../docs/rubric.html) בודק שלושה תוצרים: **פרופיל הבוגר** (לאן המגמה מכוונת), **מחוון המגמה** (מה נבדק) ו**הדגם** (מה מתקיים בפועל, כאן: פרויקט ClearPath AI). המסמך הזה מגדיר את שני הראשונים, ומראה איך הם מתחברים לפרויקט.

המחוון בנוי לפי [מודל ה-T לפרויקט גמר במגמות STEM](../docs/T-model-STEM-final-project.pdf), שהציע אבי סלמון מאינטל. לפי המודל, הפרויקט עומד על עמוד ליבה של ידע תחומי שנבדק בלי AI (A). שתי זרועות מראות מה ה-AI מאפשר להוסיף: עומק בתוך התחום (B) ורוחב לתחומים אחרים (C). ה-X מסמן רכיב אחד שהתלמיד צולל בו לעומק.

## 1. פרופיל הבוגר

בוגר המגמה שעבר את פרויקט ClearPath AI:

1. **שולט בידע הליבה** של מדעי המחשב והנדסת תוכנה: אלגוריתמים ומבני נתונים, תקשורת, בסיסי נתונים, מבנה המחשב, אבטחת מידע וביצועים. הוא מסביר אותם בלי AI. *(A)*
2. **שולט בתהליך הפיתוח**: מריץ את המערכת מאפס, מסביר את סדר הבנייה ואת היסטוריית השינויים, מדבג, ומבצע שינוי בעצמו. *(A)*
3. **מכיר רכיב אחד עד הסוף**: מסביר אותו מכמה כיוונים, מכיר חלופות ומגבלות, ומגן עליו מול כל שאלה. *(X)*
4. **בונה מערכת מורכבת בעזרת AI, ובודק אותה**: פותר בעיות שלא היו בהישג ידו, מבין את מה שה-AI הפיק, ומאמת אותו מול ראיה. *(B)*
5. **מחבר תחום דעת נוסף כשהוא משפר את הפתרון**, ומכיר את גבולות ההבנה שלו בתחום הזה. *(C)*
6. **אחראי לתוצר ושקוף בעבודה עם AI**: מתעד מה ביקש, מה קיבל ומה תיקן, מבחין בין תרומתו לתרומת ה-AI, ומתכנן מתוך שיקולי פרטיות, אתיקה ובטיחות. *(שקיפות)*
7. **מבין את מגבלות ה-AI**: יודע מתי מודל שפה או סוכן מתאימים ומתי כלל פשוט עדיף, ולמה ההחלטה במערכת קריטית נשארת אצל אדם. *(B ו-X)*

## 2. תנאי סף

1. **הדיאלוגים המלאים עם ה-AI מצורפים לקבצי הפרויקט**, בתיקייה `ai-dialogues/` ([מבנה הקבצים](templates.md#5-צירוף-הדיאלוגים-עם-ה-ai)). פרויקט בלי הדיאלוגים אינו נחשב מוגש ואינו מדורג, גם אם התוצר עובד. הסתרה של סיסמאות, מפתחות ומידע אישי מותרת ונדרשת. עריכה או מחיקה של תוכן השיחה אינה מותרת.
2. **עמוד הליבה (A).** ציון 1 ברכיב A פוסל את הפרויקט כולו, גם אם התוצר מרשים.

## 3. מחוון המגמה

המחוון בוחן חמישה רכיבים בסולם של ארבע רמות: 4 מצוין, 3 טוב, 2 בסיסי, 1 לא עומד. המשקלות לקוחים ממודל ה-T, והם הצעה לדיון. אותו מחוון משמש לתכנון, למשוב במהלך העבודה ולבחינה, כך שהתלמיד יודע מראש במה ייבחן. משוב המורה לאורך התהליך הוא איכותני, והדירוג ניתן בבחינה.

### A · ידע תחומי ושליטה בתהליך, בלי AI · 35% · תנאי סף

| רמה | תיאור |
| --- | --- |
| 4 | מסביר במדויק את מושגי הליבה שהרכיבים שלו עומדים עליהם, ופותר במקום בעיה חדשה בלי עזרה. מריץ את המערכת מאפס, מסביר את סדר הבנייה ואת ה-commits, ומבצע שינוי קטן בעצמו. |
| 3 | מסביר נכון ופותר עם רמז קטן. מריץ את המערכת ומתאר את השלבים, אבל צריך עזרה בדיבוג או בשינוי. |
| 2 | מכיר את המושגים, אבל מתקשה ליישם אותם בבעיה חדשה או לנמק החלטה במערכת. |
| 1 | אינו מסביר את הידע שהפרויקט נשען עליו, או אינו מריץ את המערכת בעצמו. **פוסל את הפרויקט.** |

**איך נבדק:** שיחה בעל פה ובעיה קצרה על הלוח, בלי מחשב ובלי AI; שיחות בדיקה בסוף כל שלב; [כישורי ההערכה](../.claude/skills/assess-core-knowledge/SKILL.md) במצב הערכה; הרצה מאפס ומשימת שינוי בבחינה.

### X · צלילה לעומק · 20%

כל תלמיד בוחר רכיב אחד בפרויקט וחוקר אותו מארבעה כיוונים: מדעי, טכנולוגי, היסטורי ואתי ([תבנית](templates.md#6-צלילה-לעומק)). דוגמאות: הגל הירוק, `A*` והיוריסטיקה שלו, מודל האיומים, מודל הסיווג, עוזר המוקדן.

| רמה | תיאור |
| --- | --- |
| 4 | עונה על כל שאלת "למה" ו"מה אם" על הרכיב, מכיר חלופות שפסל ואת המגבלות, ומסביר את הרכיב מכל ארבעת הכיוונים. |
| 3 | מסביר לעומק את הרכיב ואת ההחלטות בו, אבל מכיוון אחד או שניים. |
| 2 | מתאר מה הרכיב עושה, אבל לא למה. |
| 1 | אין רכיב שהתלמיד מכיר לעומק. |

**איך נבדק:** הבוחן בוחר נקודה ברכיב ושואל "למה ככה?", "מה היה קורה אם...?", "איזו חלופה פסלת?".

### B · זרוע ימנית: ידע בתחום עם AI · 25%

ב-ClearPath AI: סימולטור מנהטן ב-60 FPS, אפליקציית Android שמבקשת גל ירוק בזמן אמת, מודל שפה שהופך דיווח ל-JSON, ועוזר מוקדן.

| רמה | תיאור |
| --- | --- |
| 4 | פותר בעיה שמעבר לתוכנית, מבין את הפתרון ומאמת אותו מול ראיה (מדידה, השוואה, baseline) בנקודות שבהן הוא משפיע על החלטות. הפתרון בנוי מרכיבים, וההרחבה שלו נבדקה. פרטיות ובטיחות משפיעות על התכנון. |
| 3 | מרחיב את הפרויקט ומסביר את רוב התוצר. הבדיקה נעשתה בעיקר בסוף. |
| 2 | ה-AI האיץ את העבודה, אבל לא הרחיב את הידע. |
| 1 | אינו מבין את מה שה-AI הפיק. |

**איך נבדק:** התלמיד מצביע על מה שלא היה מצליח לעשות בלי AI, ומראה איך וידא שהתוצר נכון.

### C · זרוע שמאלית: ידע מחוץ לתחום עם AI · 10%

ב-ClearPath AI: הנדסת תנועה (זמן פינוי צומת לפני הגל הירוק), רפואת חירום (מה שווה דקה בזמן הגעה), פיזיקה של GPS (אותות לוויין ו-Urban Canyon), או שפות (התרעה לאזרח בשפת המכשיר). אין ציפייה לרמת מומחה.

| רמה | תיאור |
| --- | --- |
| 4 | התחום הנוסף משנה את הפתרון, החיבור מוסבר, והגבולות של מה שהתלמיד בדק מוכרים לו. |
| 3 | התחום הנוסף תורם ומוסבר ברמה סבירה. |
| 2 | התחום הנוסף מופיע, אבל מחובר באופן שטחי. |
| 1 | אין רב-תחומיות, או שהיא קישוט בלבד. |

**איך נבדק:** התלמיד מסביר למה בחר דווקא בתחום הזה, ומה הוא לא יודע בו.

### שקיפות ותיעוד העבודה עם AI · 10%

| רמה | תיאור |
| --- | --- |
| 4 | יומן AI מלא שמפנה לדיאלוגים המצורפים: כלים, בקשות, טעויות שנתפסו ותיקונים. הבחנה ברורה בין תרומת התלמיד לתרומת ה-AI, ורשומות החלטה מנומקות. |
| 3 | תיעוד של רוב השלבים. |
| 2 | תיעוד חלקי או כללי, בלי הבחנה בין התרומות. |
| 1 | אין תיעוד. |

**איך נבדק:** הבוחן עובר על יומן ה-AI ועל הדיאלוגים לפני הבחינה, ושואל על נקודה אחת מהם.

## 4. בנק שאלות לבדיקה בלי AI (רכיב A)

| רכיב | שאלה |
| --- | --- |
| ניתוב | הרץ `A*` ביד על גרף של 5 צמתים. מתי יוריסטיקה קבילה, ולמה זה חשוב? |
| סימולטור | למה הסימולטור רץ רק במחשב? מה ה-GPU עושה שה-CPU לא עושה טוב? |
| גל ירוק | אמבולנס 400 מטר מהצומת ב-15 מטר לשנייה. מתי מחליפים לירוק, ולמה מוקדם יותר? |
| Geofence | למה לא עוברים על כל האזרחים בכל עדכון? איך אינדקס רשת עוזר? |
| תקשורת | מה קורה להודעת מיקום בכל שכבה? למה WebSocket ולא HTTP? מה המחיר של TCP? |
| בסיס נתונים | שרטט את ה-ERD. מה הטרנזקציה מונעת כששני מוקדנים משייכים את אותו רכב? |
| אבטחה | איך השרת מזהה שידור חוזר? למה token של אזרח לא מקבל גל ירוק? |
| מבנה המחשב | למה `A*` רץ בתהליך Python נפרד ולא ב-thread? למה המיקומים ב-Redis המקומי ולא ב-PostgreSQL? |
| מודל שפה | מה זה temperature? למה בודקים את ה-JSON מול schema? מה זו הזיה? |
| מסווג | מה מראה ה-confusion matrix? למה אסור לבדוק על נתוני האימון? |
| ביצועים | למה p95 ולא רק ממוצע? איך בחרתם מה לשפר? |
| סוכן | מה ההבדל בין סוכן ל-workflow? מה מונע מהסוכן לשלוח רכב? מה יקרה אם הדיווח יכיל prompt injection? |
| תהליך הפיתוח | למה בניתם את השלב הזה לפני השלב ההוא? מה השתנה ב-commit הזה ולמה? כאן ה-AI הציע X ובחרת Y, למה? |

## 5. הלימה

הטבלה מראה שכל רכיב בפרופיל הבוגר נבדק במחוון ומודגם בפרויקט.

| פרופיל הבוגר | מחוון המגמה | איפה זה מודגם בפרויקט | מחוון השיפוט |
| --- | --- | --- | --- |
| 1. ידע הליבה | A, שיחות בדיקה | פרק 6 באפיון: תוצר הגנה לכל רכיב | [קריטריון 1](../docs/rubric.html#c1) |
| 2. שליטה בתהליך הפיתוח | A | הוראות הרצה, היסטוריית Git, הרצה מאפס ומשימת שינוי | [קריטריונים 1 ו-4](../docs/rubric.html#c1) |
| 3. רכיב אחד עד הסוף | X | רכיב הבעלות של כל תלמיד ותבנית הצלילה לעומק | [בונוס X](../docs/rubric.html) |
| 4. מערכת מורכבת בעזרת AI, ובדיקתה | B | המערכת המלאה, דוח הביצועים, ניסוי ההשוואה (6.6), הערכת הסוכן מול baseline (6.7) | [קריטריונים 2 ו-3](../docs/rubric.html#c2) |
| 5. תחום דעת נוסף | C | הנדסת תנועה, רפואת חירום, פיזיקת GPS | [בונוס C](../docs/rubric.html) |
| 6. אחריות ושקיפות | שקיפות, תנאי הסף | הדיאלוגים המצורפים, יומן AI, רשומות החלטה, טבלת איומים (6.1), פרטיות אזרחים | [קריטריונים 3 ו-4](../docs/rubric.html#c4) |
| 7. מגבלות ה-AI | B ו-X | ה-LLM והסוכן רק מציעים; המערכת עובדת גם בלי הסוכן | [קריטריונים 3 ו-4](../docs/rubric.html#c3) |

מחוון השיפוט מדרג מ-1 עד 5, ומחוון המגמה, לפי מודל ה-T, מ-1 עד 4. הרכיבים זהים: A הוא קריטריון 1, B הוא קריטריון 2, וזרוע C והצלילה לעומק הם הבונוסים C ו-X. ההבדל הוא שבמחוון המגמה C ו-X הם חלק מהציון, ולא בונוס.
